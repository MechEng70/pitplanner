# Pit Planner

Cook-day scheduling for smokers and griddles. Tell it what you're cooking and when dinner is, and it tells you when to fire the smoker, wrap, pull and start the griddle, with real alarms at each step.

Android app (Expo + React Native), sideloaded from GitHub Releases. 0.1.0 and 0.2.0 were built with
Capacitor; that code is in `legacy/` (reference only) and tag `v0.2.0` rebuilds it.

## What's here

- `SPEC.md`: what v1 does, decisions, screens, alarm design, failure-mode table, definition of done.
- `data/foods.json`: cooking rules (foods, methods, phases, timing). Add or tune foods here.
- `data/cookers.json`: smoker picker list. Only verified entries have specs filled in.
- `engine/`: scheduling engine in TypeScript, no dependencies. `engine/plan.test.ts` covers the Saturday plan, clear-pit rule, start-at mode, live adjustments, pit outage, DST, learning and size-adjusted timing.
- `reference/cook-day-planner.html`: the HTML planner this app replaces.
- Mockups: https://claude.ai/artifact/HTLvrL9LnmkuoPLip1v9dz

## Develop

Needs Node 22.18 or newer (the engine tests run .ts directly), JDK 21 and the Android SDK (`ANDROID_HOME`).

```
npm install
npm run android    # prebuild android/, build and install "Pit Planner dev" on the phone, start Metro
npm start          # Metro only, for an already installed dev build
npm test           # engine (node:test) and app (Jest) tests
npm run typecheck
npm run check      # full quality gate (format, lint, types, all tests, Semgrep, Snyk); see CLAUDE.md
```

The dev build (`io.github.mecheng70.pitplanner.debug`, "Pit Planner dev") installs beside the release app and
has its own data. `android/` is generated by `npx expo prebuild` and git-ignored.

- `app/`: Expo Router routes (tabs Plan, Cook, Gear). Routes stay thin; screens live in `src/screens/`.
- `src/lib/`: app logic (formatting, rules access, gear, cook state, history views); no React Native imports.
- `src/platform/`: interfaces to alarms, permissions, sharing, links and secrets (Expo implementations later).
- `docs/design/`: technical design, tasks and work breakdown.
